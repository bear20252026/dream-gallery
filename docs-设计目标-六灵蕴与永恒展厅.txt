第一卷：灵蕴飞舟（飞行器）详细设计
一、飞舟外观设计
基础造型
灵蕴飞舟是一艘融合了古风木舟与仙鹤展翅意象的飞行器。
部件 设计描述
船体 流线型木舟造型，长约3.2米，宽约1.4米，材质为深色哑光木纹（类似老榆木），表面有细密的云纹浮雕
鹤翼 船体两侧伸展出一对半透明的羽翼骨架，翼展约4.6米，骨架材质为淡金色金属质感，翼膜为半透明发光材质，呈六边形鳞片排列
鹤首 船头雕刻为简化的鹤首造型，喙部微张，内部发出六色微光
鹤尾 船尾延伸出三根细长的尾羽，长度约1.8米，随风轻微摆动
驾驶位 船体中央略靠后，一个低矮的圆形坐垫（蒲团样式），前方无物理操控装置——飞舟靠“意念”控制（实际是WASD）
六色光带 船体底部均匀分布六枚灵蕴印记，各自发对应颜色光，形成一个环绕船底的光环带
外观进化（随收集进度变化）
0颗（未解锁）：飞舟不可见，仅在地图角落留下一个淡淡的木质轮廓阴影，提示“这里曾停放过什么”
1颗（春生之芽）：飞舟基础形态出现，木质船体+鹤翼骨架，船头鹤首微亮翠绿光芒
2颗（夏炽之焰）：船体表面浮现赤红色纹路，如同木纹中渗出的火光，尾羽尖端开始发光
3颗（秋思之叶）：船身整体泛起琥珀色光泽，船体木纹变得更深、更有质感，尾羽变为琥珀色半透明
4颗（冬藏之雪）：船体表面出现霜花结晶纹理（细微的六角形冰晶图案），船舷边缘结出极薄的霜边
5颗（朝露之珠）：船首鹤目亮起天青色光芒，鹤翼边缘出现细微的光粒拖尾
6颗（暮光之尘）：全船爆发一次柔和的光波（半径5米），随后六色流光覆盖全身，船体进入“完整形态”：
部件 完整形态表现
船体 深木色转为暖金色，云纹浮雕中有六色光流动
鹤翼 翼膜变为半透明天青-暖橙渐变，六边形鳞片清晰可见
鹤首 双目放出稳定的六色光芒，喙部微光持续溢出
尾羽 三根尾羽呈琥珀-天青-暖橙渐变，末端有光粒飘散
底部光环 六枚灵蕴印记形成完整光环，缓慢旋转
飞舟状态与位置
状态 位置
未解锁（0-5颗） 停放在昆仑山巅北侧一块突出的岩石平台上，被一层半透明结界笼罩，可看到轮廓但无法靠近（结界会推开玩家）
已解锁（6颗） 结界消散，飞舟完全显现，发光，可交互“按E登上飞舟”
二、六条航路详细设计
航路通用参数
参数 数值
每条航路长度 约500-800米（飞行约8-12秒）
航路宽度 约20米（飞行器可自由在航路内小幅度偏移）
航路高度 从地面100米至3000米，逐条上升
航路间隔 每条航路之间有约2秒的过渡区（云层间隙）
飞行速度 约25米/秒（自动飞行模式）
航路一：东线·朝霞航路
项目 描述
视觉背景 东面地平线呈现金色-粉橙渐变霞光，云层被染成暖橘色，海面在远处如镜面般反射天光
天空盒颜色 底部#FF7B4A → 中部#FFB76D → 顶部#FFE4B5
粒子特效 金色微粒从下往上漂浮，密度中等，大小约0.02-0.05单位，飘落速度极慢
航路标记 两侧各有一排金色光点，呈线性排列，间距约1.5米
云层设置 低层散云（覆盖率约40%），高度120-180米，云朵为半透明白色，边缘带淡金
音效 极轻的风声，带有高频的细微叮当声（类似风铃在远处），音量-25dB
背景音乐 弦乐长音+竖琴琶音，C大调，缓慢
特效亮点 飞舟经过时，两侧光点会短暂增亮，形成一条“光之路”
情感色调 温暖、开阔、初升
航路二：南线·炽阳航路
项目 描述
视觉背景 南面天空呈现深橙-赤红渐变，仿佛正午烈日被雾气柔化，空中偶尔飘过暗红色的“热浪波纹”（半透明扭曲效果）
天空盒颜色 底部#D4380D → 中部#FF7A00 → 顶部#FFB347
粒子特效 赤红色火星从下方缓缓上升，密度较高，火星闪烁频率约1.5Hz，同时有横向流动的暖色光带（如热浪）
航路标记 两侧各有一排微型火焰状光点，呈橙红色，轻微跳动
云层设置 无云层（被高温“蒸发”），只有极淡的雾状尘埃，呈暖色调
音效 低频持续的轰鸣声（类似远处炉火），叠加偶尔的“噼啪”声，音量-30dB

特效亮点 飞舟经过时，航路两侧的“火焰光点”会拉出短暂的光弧，仿佛被飞舟的气流扰动

航路三：西线·暮色航路
项目 描述

云层设置 高层薄云（覆盖率约60%），云朵为淡紫色-暖橙渐变，高度200-300米，呈拉长丝带状

航路四：北线·寒夜航路
项目 描述

航路五：天顶线·破晓航路
项目 描述

三、航路飞行体验流程
第一次飞行（自动引导，不可操控）
1. 登上飞舟：玩家按E登上飞舟，视角切换为驾驶舱视角（第一人称或第三人称可选）
2. 起飞：飞舟底部光环旋转加速→船体缓缓上升→加速→冲向云层
3. 进入云海：穿越云层（约2秒纯白画面），玩家视线被云遮蔽后重新打开
4. 第一航路（东线·朝霞）：飞舟自动沿东线飞行，同时显示“春生之芽·朝霞航路”，TTS播放短诗
5. 过渡（2秒）：飞舟穿过一片淡金色光幕，进入第二航路
6. 第二航路（南线·炽阳）：显示“夏炽之焰·炽阳航路”，TTS播放短诗
7. 过渡（2秒）：穿过一片暖橙色光幕
8. 第三航路（西线·暮色）：显示“秋思之叶·暮色航路”，TTS播放短诗
9. 过渡（2秒）：穿过一片琥珀色光幕
10. 第四航路（北线·寒夜）：显示“冬藏之雪·寒夜航路”，TTS播放短诗
11. 过渡（2秒）：穿过一片霜白色光幕
12. 第五航路（天顶线·破晓）：显示“朝露之珠·破晓航路”，TTS播放短诗
13. 过渡（2秒）：穿过一片天青色光幕
14. 第六航路（归途线·合光）：显示“暮光之尘·合光航路”，TTS播放短诗
15. 抵达：云海散开，永恒展厅出现在前方，飞舟自动减速→接近平台→停靠→画面微震→提示按E离开飞舟
总计自动飞行时间：约60-70秒
后续飞行（手动操控，自由探索）
第一次自动飞行后，玩家可在昆仑山巅重新登上飞舟，手动操控飞行：
· 可自由飞往六条航路中的任何一条
· 每条航路都设有悬浮平台（小型浮空石台），可降落停留、观看风景
· 航路终点处可折返或继续上升/下降
· 永恒展厅始终悬浮在最高处，可随时飞回

二、飞舟系统技术要点
模块 方案
飞行物理 简化物理，用CharacterController + 自定义运动逻辑，不启用真实物理重力
自动飞行 预置AnimationCurve轨道，飞舟沿轨道移动，玩家仅可控制视角
手动飞行 WASD控制移动方向，Space冲刺（用Timeline/Sequencer控制加速）
航路切换 飞舟进入航路Trigger区域时，触发对应的粒子系统+天空盒切换
粒子系统 每条航路独立粒子系统，通过区域Trigger控制激活/停用
飞舟外观变化 收集进度通过MaterialPropertyBlock控制颜色变化
三、空中永恒展厅技术要点
模块 方案
展厅加载 在飞行过程中异步加载（Addressables/Streaming Level），飞行结束时已就绪
悬浮表现 底部光柱用VolumeLight + 粒子系统实现，建筑本身无物理重力
交互触发 所有交互用Raycast + 碰撞体检测
晨光留影 用SpotLight + 体积光，记录最早3张照片ID，在光照范围内
暖色壁炉 粒子系统（火焰+火星）+ 屏幕后期调色（靠近时）
风铃回响 Animator控制摆动动画 + AudioSource播放音效
飘雪之窗 粒子系统（雪）+ Shader（照片覆盖层）+ Bool控制开/关
重置视角 DOTween/LeanTween控制照片移动动画 + 粒子系统（光粒拖尾）
放下 Shader（消解效果）+ 粒子系统（微粒扩散）+ 状态切换（照片/空画框）
俯瞰天穹 Cinemachine/LevelSequence控制镜头切换 + Trigger检测玩家位置
心象投影 用RenderTexture + 预录或实时画面叠加 + 定时序列控制
灵蕴归位 按钮点击 + 状态记录 + 全部完成后触发全局事件
四、异步加载方案
玩家登上飞舟 → 触发起飞动画
    ↓
同时触发永恒展厅的异步加载（Addressables.LoadSceneAsync）
    ↓
飞行过程中（60秒），后台加载永恒展厅场景
    ↓
飞舟抵达 → 永恒展厅已加载完毕 → 平滑切换场景/传送玩家
加载策略 说明
预加载时机 飞舟起飞时即开始加载
加载方式 后台异步加载，不阻塞主线程
加载完成前 不显示任何加载界面（玩家在飞行中，无感知）
加载完成后 场景就绪，等待飞舟抵达后自动切换
内存管理 地面场景在玩家进入空中展厅后逐步释放
五、C#代码示例（Unity）
飞舟控制
public class LingYunBoat : MonoBehaviour
{
    public float flySpeed = 25f;
    public float sprintSpeed = 40f;
    public float rotationSpeed = 3f;
    public float sprintDuration = 3f;
    public float sprintCooldown = 15f;
    
    private bool isAutoPilot = true;
    private float currentSpeed;
    private float sprintTimer;
    private bool canSprint = true;
    
    void Update()
    {
        if (isAutoPilot)
        {
            // 自动飞行：沿预设轨道移动
            FollowPath();
        }
        else
        {
            // 手动飞行：WASD控制
            float h = Input.GetAxis("Horizontal");
            float v = Input.GetAxis("Vertical");
            
            transform.Translate(Vector3.forward * v * currentSpeed * Time.deltaTime);
            transform.Rotate(Vector3.up * h * rotationSpeed * Time.deltaTime);
            
            if (Input.GetKeyDown(KeyCode.Space) && canSprint)
            {
                StartCoroutine(Sprint());
            }
        }
    }
    
    IEnumerator Sprint()
    {
        canSprint = false;
        currentSpeed = sprintSpeed;
        yield return new WaitForSeconds(sprintDuration);
        currentSpeed = flySpeed;
        yield return new WaitForSeconds(sprintCooldown);
        canSprint = true;
    }
}
放下交互
public class LetGoInteraction : MonoBehaviour
{
    public float holdDuration = 3f;
    private float holdTimer;
    private bool isHolding;
    private GameObject targetPhoto;
    
    void Update()
    {
        if (Input.GetMouseButtonDown(0))
        {
            Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);
            if (Physics.Raycast(ray, out RaycastHit hit) && hit.collider.CompareTag("Photo"))
            {
                targetPhoto = hit.collider.gameObject;
                isHolding = true;
                holdTimer = 0f;
                // 显示环形进度条
            }
        }
        
        if (Input.GetMouseButton(0) && isHolding)
        {
            holdTimer += Time.deltaTime;
            // 更新进度条UI
            
            if (holdTimer >= holdDuration)
            {
                TriggerLetGo(targetPhoto);
                isHolding = false;
            }
        }
        
        if (Input.GetMouseButtonUp(0))
        {
            isHolding = false;
            // 隐藏进度条
        }
    }
    
    void TriggerLetGo(GameObject photo)
    {
        // 播放消解粒子效果
        // 将照片切换为空画框
        // 记录到放下列表
    }
}

### 二、收集顺序的灵活性

**原则**：玩家不必按顺序收集六颗灵蕴。系统只会**揭示下一颗的位置**，但玩家可以**自由探索**并提前发现其他灵蕴。

| 情况 | 处理方式 |
|------|---------|
| 系统揭示春生之芽，但玩家先走到了夏炽之焰的位置 | 可以提前拾取夏炽之焰，拾取后系统自动切换下一颗揭示目标 |
| 玩家在探索中偶然发现了未被揭示的灵蕴 | 拾取时触发“你发现了一颗未被标记的灵蕴”文案，系统记录并调整揭示顺序 |
| 玩家只收集了3颗就停止主线探索 | 补天进度仍然可继续，但六灵蕴任务不会消失，罗盘内始终可查看未收集状态 |
| 玩家收集顺序与系统揭示顺序不同 | 最终六颗全部集齐后的效果完全一致，顺序不影响结局 |

## 第十卷：异常情况处理


### 一、飞舟飞行中的异常

| 异常 | 处理方式 |
|------|---------|
| 玩家离开游戏（飞行中） | 重新登录后，飞舟停留在最近的安全位置（地面或永恒展厅） |
| 飞行中掉线重连 | 重连后飞舟原地悬停，继续飞行 |
| 操作卡顿导致撞山（理论无碰撞） | 飞舟穿过山体（无物理碰撞），但画面短暂变暗提示“穿过云层” |
| 玩家想要提前结束飞行 | 按ESC→选择“立即抵达”→直接传送至目的地 |


### 二、灵蕴收集中的异常

| 异常 | 处理方式 |
|------|---------|
| 玩家在地图标记位置找不到灵蕴 | 走近后光柱自动显现（标记位置准确，无需解谜） |
| 玩家用飞行器跳过了某颗灵蕴 | 该灵蕴仍然保留在地图上，可随时返回收集 |
| 收集某颗灵蕴后系统没有解锁下一颗 | 罗盘手动刷新/重启游戏后状态恢复 |
| 玩家在未解锁阶段偶然获得某颗灵蕴 | 灵蕴数据仍然存储，系统标记为“已收集”，但航线不会解锁，直到正式触发该阶段时才解锁对应航线（已收集的灵蕴会在界面上直接显示为“已收集”，其他玩家正常推进） |


### 三、永恒展厅交互异常

| 异常 | 处理方式 |
|------|---------|
| 交互点无响应 | 保存当前数据→重新加载展厅场景 |
| “放下”的照片无法找回 | 召回功能永久可用，存储在数据库中 |
| 晨光留影识别错了最早照片 | 如果玩家有删除/重新上传照片的行为，系统以当前上传时间戳为准，自动刷新“最早三张”列表 |
| 风铃不响了 | 检查音频系统，如无响应则通过UI文字替代提示 |

**《梦幻画廊》的完整旅程，是一条从“修补世界”走向“认识自己”，最终抵达“云端归宿”的路。每一步，都有昆仑替你记得。** 🌤️
有的。
整个对话下来，我们搭建了一个从“地面补天”到“空中归宿”的完整神话闭环。但还有一个东西没碰——游戏的“冷启动”界面。
就是玩家第一次打开《梦幻画廊》，还没开始十道题之前，看到的第一眼。
这个界面决定了玩家愿不愿意往下走。我建议加一个30秒的互动序章，不弹窗、不读条，只做三件事：
1. 一片漆黑中，一句旁白响起：“三千年了。”
2. 画面缓缓亮起，玩家发现自己站在一座空旷的山巅，面前悬浮着一面巨大的残镜。镜面龟裂，布满灰尘。没有任何UI，没有任何提示。
3. 残镜中开始回放画面：女娲碎石的慢镜头、微尘落入人间的瞬间、无数张照片在风中翻飞……回放结束，残镜恢复寂静。镜面上缓缓浮现一行字：“你愿意让它重新亮起来吗？”
画面下方只出现两个选项：“我愿意” 和 “让我再想想”。
如果选“我愿意”，残镜裂痕消退，镜面泛起金光，直接进入心象共鸣。如果选“让我再想想”，画面不关闭，但残镜保持暗淡——玩家随时可以回头点击镜面重新选择。
——这个序章不涉及任何新功能，只需要一个场景+一面镜+一段30秒的预渲染动画。但它解决的是一件事：让玩家在上传第一张照片之前，就已经知道自己“正在参与女娲最后的遗愿”。
---
如果你觉得这个方向值得加进去，我可以继续展开它的分镜、场景布局、以及与后续心象共鸣的衔接逻辑。或者你觉得还有什么其他角落被我遗漏了，也可以直接告诉我。😊好。从头开始，完完整整走一遍。

整个流程走完了。
从一个在黑暗中面对残镜的陌生人，到登上天空之殿被完整念出全名的六合藏梦人——所有神话、所有操作、所有交互、所有TTS语音、所有UI反馈，全部串联成一条从地面到天空的完整旅程。
还有遗漏吗？ 😊有的。我列一下所有需要额外注意的事项：
---
一、开发层面
1. 跨平台兼容
平台 注意事项
PC端（Unity/Unreal） 所有交互正常，WASD+鼠标
移动端 触屏操作需要重新映射（摇杆+点击），长按3秒“放下”在手机上改为长按触屏，需增加触觉反馈
Web端（如用Three.js） 飞舟自动飞行的粒子数量需要降低30-50%，永恒展厅交互改用点击而非悬停
1. 性能优化
项目 建议
玩家设备差异 提供“低画质模式”（关闭体积云/降低粒子数量/减少光影）
粒子数量 航路粒子不宜超过200个/条，永恒展厅飘雪粒子不超过150个
加载时间 永恒展厅异步加载时，如果玩家网络慢，飞行过程中可显示“云层加载中……”不影响飞行体验
内存管理 地面展厅和空中展厅分两个场景，进入空中后逐步释放地面资源
1. 数据存储安全
数据 注意事项
玩家上传照片 不得存储在本地缓存，服务器端加密存储
隐私 支持玩家“删除已上传照片”，删除后从服务器永久移除
进度数据 实时云端保存（每次里程碑触发时保存一次），防止断线丢失
二、叙事与体验层面
1. “放下”功能的用户体验注意
· 长按3秒触发“放下”，需提供进度条提示
· 放下后玩家可能后悔，必须有“召回”功能
· 空画框的余影需保留足够长的时间让玩家感到“它曾存在过”的重量
· 放下超过3张时的提示文案：“昆仑已替你放下了足够多的过去。”——语气需温柔而非责备
1. 里程碑反馈的频率
· 日常操作时，不能过于频繁打断玩家
· 仅里程碑（5%,10%,20%...）和大事件（天穹闭合/六灵蕴集齐）触发大弹窗+TTS
· 日常上传时仅显示“灵蕴+5”轻提示，不触发TTS（避免语音疲劳）
1. 情感节奏控制
阶段 节奏设计
心象共鸣 安静、专注、严肃（玩家全心投入答题）
0-50%补天 逐渐温暖，每10-15%一个里程碑，提供稳定正反馈
50-100%补天 节奏加快，里程碑间距缩短（从10%缩到5%），制造“接近终点”的紧迫感
六灵蕴收集 每颗灵蕴之间留足空间，让玩家有时间消化情感，不要连续收集
六条航路飞行 60秒连续短诗——节奏紧凑但有起伏，短诗间隔约10秒，刚好让玩家喘息
1. 防止“游戏化疲劳”
· 不设“每日任务”、不设“强制在线”、不设“限时活动”
· 玩家可以随时暂停、随时离开、随时回来
· 永恒展厅没有任何计时器或倒计时，它是一个真正的“永恒”空间
三、内容安全层面
1. 用户上传内容审核
内容 处理
图片 需自动检测NSFW/敏感内容，违规图片拒绝上传并提示“这片灵蕴暂时无法归位”
涂鸦 仅限本地保存，不自动上传云端（避免不当内容传播）
链接 需校验URL安全性，禁止JS注入/钓鱼网站
四、推广与展示层面
1. 冷启动的“第一款印象”
· 序章的30秒互动（残镜+选择）是决定玩家去留的关键窗口
· 残镜回放中女娲碎石的画面务必精致，这是整个游戏的“文化名片”
· 第一次弹窗“三千年来，第一个带着真意推开这扇门的，是你”——这是唯一一次让玩家感到“我是唯一的”，之后不再重复
1. 玩家“被看见”的设计
· 永恒展厅中“心象投影”的旅途剪影，建议画面边缘带有该玩家上传的第一张照片的残影（作为水印背景）
· 称号“六合藏梦人”显示在玩家档案中，访问其他玩家的永恒展厅时能看到对方的完整称号
· 所有灵蕴收集完成后，在个人资料页显示六枚灵蕴的成就徽章，排成六边形
1. 如果玩家只上传了几张照片就退出
· 不要发送“你还有照片未上传”的推送通知
· 可以静默保留进度，下次登录时残镜上出现一行小字：“上次你带来了几片灵蕴。它们还在等你。”
· 尊重玩家的节奏
1. “永恒展厅”的命名建议
· 如果后续还想增加其他功能，建议命名为“心象圣殿”或“归处”
· “永恒展厅”这个名字侧重于空间，“心象圣殿”侧重于意义
五、对项目整体管理的补充
1. 明确开发边界
· 游戏的核心是“上传照片+布展+补天神话”——所有功能都应服务于这个核心
· 任何扩展功能（如社交、多人、排行榜）都应放在核心功能完成之后再考虑
· 空中永恒展厅不是“DLC”，是游戏本体的一部分——但它必须是“隐藏式”的
1. 版本里程碑建议
版本 内容 目的
v0.5 心象共鸣+上传照片+补天进度0-100% 验证核心玩法
v0.7 六灵蕴地面收集+飞舟基础形态+三条航路 验证收集扩展
v0.9 六条航路完整+空中永恒展厅基础场景+三项基础交互 验证最终体验
v1.0 全功能整合+六项交互完整+称号系统+全流程测试通过 正式上线
1. 重要：TTS的中文支持
· KittenTTS原生模型英文为主，中文效果待验证
· 建议先部署Kokoro-onnx（中文优化版），再考虑切换
· 如果TTS不理想，至少保证所有文案在屏幕上可读——语音是加分项，不是必选项
1. 玩家流失预警点
· 心象共鸣十道题如果太长 → 玩家可能中途退出（建议每5题触发一次轻反馈“你已经完成了一半的女娲问心”）
· 补天进度30-50%之间（如果玩家不积极上传照片）→ 可能觉得慢（建议此时地图上自动出现一个“昆仑裂隙”小彩蛋，鼓励探索）
· 六灵蕴收集过程中如果位置太远 → 玩家可能中途放弃（建议每收集一颗后，系统自动短暂标记下一颗的位置，且提示飞行方向）
1. 音乐/音效的“少即是多”
· 不要在所有交互上都播放音效——留白本身就是一种氛围
· 永恒展厅中除了风铃，其他交互应保持安静或极轻的环境音
· 六条航路中，每条航路的背景音乐建议为纯乐器（无歌词）
六、最后一句
所有的设计、所有的话术、所有的机制——最终都指向同一个目的：让一个普通的、拿着手机相册的人，在走出昆仑时，觉得自己的记忆是有重量的。
如果你在接下来的开发中遇到具体问题（比如某个交互的技术实现、某段文案的调整、某个进度的测试数据），随时来问。我一直在。😊最后的要补上的是玩家不能删除服务器的数据。，包括他自己上传的照片，他可以上传他展厅里的照片，这个可以让他删除，但这只是不在他展厅呈现，但仍在服务器里保存
